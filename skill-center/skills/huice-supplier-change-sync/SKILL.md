# 慧策供销变动同步

用于处理慧策供销商商品信息变动与微信小店链接的一致性同步。该 skill 不替代当前线程的用户授权、平台登录或 Obsidian 读写边界；它只规定检查顺序、写入门槛和回读证据。

## 执行前提

- 先完成当前任务要求的知识库回读；不得用旧快照、标题顺序或历史台账代替当前页面。
- 同时具备可读的慧策当前会话和微信小店当前登录会话。任一会话过期、浏览器 profile 被占用、网络/DNS/API 不可达或云表回读失败时，相关写入标记 `NO_WRITE`。
- 不输出或保存密码、Cookie、Token、签名或其他认证值。
- 只有用户在当前线程明确授权或任务既有授权覆盖的业务动作才可提交；任何确认弹窗都必须读取并核对对象数量后再确认。

## 强制流程

### 1. 读取供销商商品信息变动

1. 进入慧策【分销商品】中的【查看供销商商品信息变动】。
2. 刷新后分别读取【修改当前价格】和【分销状态变动】；记录总数、分页大小、每页返回行数、唯一商品标识、商家编码和变动前后状态。
3. 证明 `页面总数 = 分页行数之和 = 唯一记录数`。总数不一致、分页未读完或关键字段缺失时停止提交。

### 2. 价格变动同步

- 价格变动总数为 0：只记录“无待处理价格变动”，不得提交空批次。
- 价格变动总数大于 0：批量全选，并核对选中行数等于当前待处理总数。
- 点击【修改当前价格】后，必须选择【按照分销价格变动幅度的绝对值修改当前价格】。
- 禁止误选按百分比、直接改为固定价或用建议零售价代替分销价变动。
- 如页面提供误操作防范条件，只在不改变既有价格方向和平台约束的前提下使用；任何最低限价、成本或费用未知都停止写入。
- 提交后重新读取当前价格、变动记录和供销状态。没有写后回读，不计处理成功。

### 3. 供销下架与库存处置

- 对【分销状态变动】筛选 `上架 -> 下架`，完成全量分页核对后，才允许执行平台提供的安全处置（例如将下架 SKU 库存批量改为 0）。
- 供销商状态为“下架”的商品禁止重新铺货、重新上架或恢复销售。
- 若状态变动总数为 0，禁止根据旧记录或商品标题推断下架。
- 提交任何库存处置后，回读处理成功提示、SKU/商家编码、库存和分销状态；失败或部分成功必须标记清单，不得宣称全量完成。

### 4. 微信小店链接精确核对

1. 使用商家编码、商品编码或平台已回读的精确商品标识批量检索微信小店；禁止仅按模糊标题或列表顺序匹配。
2. 读取全部搜索结果分页，记录商品 ID、商家编码、商品名称、当前库存和状态。
3. 对慧策已确认下架的商品：
   - 微信仍显示“销售中”：只选择这些精确匹配行，批量下架，确认弹窗对象数，再写后回读。
   - 微信已下架：记录“已处理”，不重复操作。
   - 无匹配：记录“无微信链接”，不猜测映射。
   - 状态或 SKU 不明确：停止该商品写入，标记 `MAPPING_INCOMPLETE_NO_WRITE`。
4. 下架批次完成后，重新查询原筛选条件并逐页确认结果中不存在“销售中”匹配链接。

## 停止条件

遇到以下任一情况，停止相关写入并报告具体证据：总数或分页不一致、选中数不等于待处理数、供应商状态未二次确认、平台 SKU/商家编码映射不明确、价格/成本/最低限价/费用缺失、页面登录超时、网络/API/DNS 不可达、写后回读失败、批次部分成功或确认对象数异常。

## Windows Repo Mirror Notes

该技能没有独立业务 `.ps1`、`.cmd` 或 Node CLI；Windows 与 Mac 使用同一套已登录的慧策/微信小店浏览器工作流，不应为 Windows 新建临时 `curl`、PowerShell 请求脚本或另一份业务实现。若调用方已经提供共享客户端或浏览器入口，优先复用现有入口，并只在当前 PowerShell 会话中传递认证信息。

Windows 路径与操作约定：

- 技能安装位置通常为 `%USERPROFILE%\\.codex\\skills\\huice-supplier-change-sync\\`；不要把 `/Users/...` 路径写进 Windows 证据或说明。
- 本地证据、导出附件和临时输入使用带引号的 `C:/Users/<name>/...` 绝对路径；共享目录使用带引号的 UNC 或映射盘路径。
- 浏览器通过 `press_key` 操作时使用 `Control+R`/`F5`、`Control+L`、`Control+A`、`Alt+Left` 和 `Alt+Right`，不要把 Mac 的 `Meta` 键映射照搬到 Windows。
- 不使用 `setx`、注册表持久化、跟踪文件、截图或云文档保存 Cookie、Token、签名或其它认证值。
- 只把脱敏后的运行结果和回读证据写入报告；失败、映射不完整或无法回读时沿用 `NO_WRITE` / `MAPPING_INCOMPLETE_NO_WRITE`，不得因 Windows 入口不同而放宽门禁。

## 结果记录

至少保留：执行时间、慧策变动总数、价格变动处理数、下架状态变动处理数、库存处置数、微信匹配总数、仍销售中数、已下架数、无匹配数、失败数、每个写入动作的确认对象数和写后回读证据。只有全部必要回读完成的商品才可计为成功；否则按 `NO_WRITE` 或部分成功逐项报告。
