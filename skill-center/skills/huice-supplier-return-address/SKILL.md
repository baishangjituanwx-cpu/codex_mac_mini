# 慧策供应商售后退货地址

## 用途

当商品详情接口和云表格中都没有可执行的售后地址时，读取慧策“分析 → 供应商管理 → 供销商售后退货地址”，按商品对应供应商精确匹配地址，作为备用售后地址来源。这个技能只解决地址来源判定，不替代商品映射、类目、资质、价格、库存或毛利门禁。

## 地址优先级

每个商品、每次关键检查点都按以下顺序实时判定：

1. 一般商品：优先使用当前 `goods_detail` 返回的完整售后地址。
2. 牙博士商品：使用云表格 `退货售后地址` 中“牙博士所有商品”这一条专用地址；它优先于 `goods_detail`，并且每轮铺货前必须重新读取。
3. 若前两项不可用，再读取慧策“供销商售后退货地址”，使用商品对应供应商提供的完整地址。
4. 三个来源都没有完整地址、供应商身份不确定、供应商匹配不唯一或地址记录为“供应商未维护”时，标记为“售后地址待补充/供应商地址不可用”，禁止铺货、重发和计入硬成功。

供应商地址是备用来源，不得覆盖已有的完整商品详情地址或牙博士专用地址，也不得仅凭商品标题、供应商简称、商家编码或模糊相似名称猜测供应商。

## 完整地址标准

地址必须同时具备：

- 收件人姓名；
- 联系电话。对外记录只保留脱敏号码，不输出明文手机号；
- 省、市、区/县；
- 详细地址，且不是“供应商未维护”、空值、掩码或占位文本。

只显示公司名、联系人和电话但没有省市区及详细地址，不算完整地址。供应商页面只展示“供货商未维护”或同类提示时，不得把它当作地址。

## 精确匹配流程

### 1. 锁定商品和供应商

先保存当前事实：`supplierShopId`、`supplierGoodsId`、商品名称、供应商名称，以及必要的 `distributorGoodsId`、`itemId`。供应商名称必须来自当前慧策商品/分销详情或当前供应商关系，不使用历史台账猜测。

### 2. 读取供应商地址页

通过共享慧策 HTTP API读取“供销商售后退货地址”对应接口；浏览器在慧策域只用于确认登录上下文、临时认证和请求契约，不点击业务按钮代替 HTTP 操作。拉取全量分页或按精确供应商筛选后回读，保留供应商名称、地址完整度、来源时间和记录状态。

若当前接口契约尚未确认，先做只读契约探测：确认请求路径、方法、分页字段、供应商字段和地址字段，再做真实读取。不得凭截图臆造接口或地址字段。

已确认的页面路径、接口、字段和读取约束见 [`references/source-contract.md`](references/source-contract.md)；页面或接口契约变化时，先更新该参考文件，再恢复候选扫描。

### 3. 精确匹配与脱敏

按稳定供应商标识优先匹配：

```text
supplierShopId / supplierSysShopId
> 供应商公司精确名称
> 当前页面提供的唯一供应商编码
```

只允许得到一条完整地址记录时通过。若同一供应商有多条地址，必须再按商品对应供应商编码、店铺、默认退货标记或当前业务规则确认；无法唯一确定时不放行。不要按标题中的产地、品牌、地区或相似公司名推断供应商。

### 4. 写入与发布前复核

将地址来源记录为中文“慧策供销商售后退货地址”，并保存脱敏后的地址摘要；电话只写掩码。把供应商地址作为本次铺货的候选退货地址，按微信小店地址簿的地址 ID 精确复用或新增，新增前必须核对完整省市区、详细地址和联系人。

在铺货保存前、铺货提交前、官方销售硬回查前、创建普通推广/平台活动前再次确认来源、供应商匹配和地址 ID。地址来源发生变化时，以本轮实时读取为准，不复用历史快照。

## Windows Repo Mirror Notes

Windows 使用与 Mac 相同的共享慧策 HTTP 客户端和只读接口契约；本技能没有独立业务 `.ps1` 或 `.cmd` 入口，也不应为 Windows 改写成临时 `curl` 或一次性 PowerShell 请求。若共享客户端提供 PowerShell 启动器，优先调用已有启动器，并在当前会话中传递认证信息，不使用 `setx` 或把 cookie/token 写入文件。

Windows 路径规则：

- 技能安装位置通常为 `%USERPROFILE%\\.codex\\skills\\huice-supplier-return-address\\`；
- 共享客户端的 Mac 挂载路径 `/Volumes/BSJT 共享给我/AI专用/[Codex]Mac部署/旺店通/huice-goods-analysis` 在 Windows 上替换为带引号的 UNC 或映射盘路径，例如 `\\\\BSJT168\\BSJT 共享给我\\AI专用\\[Codex]Mac部署\\旺店通\\huice-goods-analysis`；
- 证据、导出和复制附件使用带引号的 `C:/Users/<name>/...` 绝对路径，不把 `/Users/...` 写入 Windows 记录；
- 浏览器通过 `press_key` 操作时使用 `Control+R`/`F5`、`Control+L`、`Control+A`、`Alt+Left` 和 `Alt+Right`，不要把 Mac 的 `Meta` 键映射照搬到 Windows。

供应商接口契约和地址字段见 [`references/source-contract.md`](references/source-contract.md)。

## 与其它门禁的关系

供应商地址可用只表示售后地址门通过，不代表商品可发布。仍必须通过：

- 当前 `controlMinPrice` 和目标售价门禁；
- 10%普通推广后毛利额大于 0 且毛利率严格大于 2%；
- 无推广安全毛利率不低于 8%；
- 当前 SKU、库存、类目、资质、发布记录和平台商品/SKU 精确映射；
- 当前微信小店实际售价、库存和销售状态回读。

任何其它门禁失败时，不得用供应商地址掩盖失败原因。

## 状态与写入口径

建议使用中文状态说明：

- `商品详情地址`：商品详情接口存在完整地址；
- `牙博士专用地址`：使用云表格专用地址；
- `慧策供销商售后退货地址`：使用供应商地址页的唯一完整匹配；
- `售后地址待补充`：没有任何完整来源；
- `供应商地址匹配不唯一`：存在多条候选，未写入业务数据；
- `供应商身份无法确认`：无法建立商品到供应商的精确关系；
- `供应商地址未维护`：页面明确显示未维护或地址不完整。

不要把 `MISSING_CURRENT_COST`、`ADDRESS_INCOMPLETE` 等机器状态码直接写入面向业务人员的描述列。机器状态可保留在专用代码字段，中文原因写入说明列。

## 禁止事项

- 不把供应商地址当作商品详情地址来源；必须记录真实来源。
- 不使用不完整、掩码、默认占位或供应商未维护的地址。
- 不按标题猜供应商，不按名称模糊匹配后直接发布。
- 不输出明文手机号、Cookie、token、签名或登录凭据。
- 不因地址补齐就跳过类目、资质、最低限价、毛利和精确映射检查。
- 供应商地址读取失败时只记录“供应商地址读取失败，未写入”，不执行铺货或发布。

## 结果汇报

每个商品汇报：商品 ID、供应商名称/稳定 ID、地址来源、地址是否完整、微信小店地址 ID（如已取得）、其它未通过门禁的原因，以及是否写入或发布。电话只使用脱敏形式；没有完整匹配时明确写“未放行”。
