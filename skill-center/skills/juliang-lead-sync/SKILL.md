# 巨量线索同步固定流程

## 目标

在每次巨量投放启用后，只要发现有新增线索，就立即把飞鱼 CRM 中的完整线索信息同步到指定飞书表格，并保证人工跟进可用。

## Windows 入口

- Windows 上优先复用当前已登录的 Chrome 标签页、CDP 会话或 Codex Chrome Extension 接管，不要重新走账号密码登录。
- 不要读取 cookies、localStorage、浏览器密码库，优先从当前可见的青鸟线索通或飞鱼 CRM 页面继续操作。
- Windows PowerShell 下执行 `lark-cli` 时，优先用单引号包住 JSON 参数，避免转义破坏:

## 表格列顺序

必须按这个顺序写入，不要随意换列：

1. `跟进状态`
2. `录入时间`
3. `线索姓名`
4. `手机号`
5. `线索创建时间`
6. `最近入池时间`
7. `所在城市`
8. `手机号归属地`
9. `线索类型`
10. `线索渠道`
11. `流量来源`
12. `转化状态`
13. `落地页链接`
14. `判断/备注`
15. `建议动作`

日期列要求：

- `录入时间` 写入真实日期值，并设置日期格式。
- `线索创建时间`、`最近入池时间` 写入真实日期/日期时间值，不能写成普通文本。
- 如果飞书日期时间格式不支持精确显示到秒，至少保证底层值是日期数字，方便按年月日筛选。

## 新线索触发条件

当出现以下任一情况，立即执行本 Skill：

- 投放后台 `转化数/线索数` 增加。
- 飞鱼首页显示 `新增线索量` 增加。
- 飞鱼 `线索公海`、`销售线索`、`待分配线索` 出现新记录。
- 用户要求查看新线索、客户手机号、人工联系名单、录入飞书表。
- 投放达到阶段阈值暂停后，需要整理当轮线索。

## 投放轮次更新规则

当用户开启一轮新的巨量投放测试，例如“今天 15:00 开启新一轮投放”，必须按“投放轮次”处理线索同步：

1. 开启投放前记录本轮关键信息：项目 ID、单元 ID、开始时间、预算、暂停阈值、目标落地页。
2. 默认暂停阈值为累计消耗 `>=100元`，除非用户另行指定。
3. 投放运行期间按用户设定频率检查数据；如果消耗未达到阈值，只报告投放数据，不提前写入本轮 Sheet 汇总，除非用户明确要求实时入表。
4. 当累计消耗达到或超过暂停阈值时，先暂停目标项目/单元。
5. 暂停成功后，立即进入飞鱼 CRM，按本轮开始时间到暂停时间筛选新增线索。
6. 只整理本轮新增线索；旧线索、测试线索、重复线索要区分标记。
7. 整理完成后再写入飞书 Sheet，新增行必须包含完整可见手机号和完整来源信息。
8. 写入完成后，报告本轮投放数据、线索数量、入表数量、重复/测试/异常线索数量，以及下一步人工跟进建议。

优先级规则：

- 如果用户说“每有新线索立即录入”，按实时录入执行。
- 如果用户说“投放满 100 元后整理/录入”，按投放轮次更新规则执行。
- 如果没有明确说明，默认采用投放轮次规则：达到暂停阈值后统一整理并写入 Sheet。

## 完整线索字段要求

每条新增线索必须尽量读取以下字段：

- 姓名
- 完整可见手机号
- 线索创建时间
- 最近入池时间
- 所在城市
- 手机号归属地
- 线索类型
- 线索渠道
- 线索渠道详情（如页面提供）
- 流量来源
- 转化状态
- 落地页链接
- 跟进状态
- 通话状态
- 客户名称或客户 ID（如页面提供）

手机号规则：

- 写入飞书表前，必须确认手机号是完整可见号码，不是 `133****1234` 这类脱敏号码。
- 如果只能看到脱敏号码，先尝试飞鱼内的 `查看号码/披露号码/解密` 等合规入口。
- 如果仍不可见，不要把该线索当作“完整可跟进线索”写入正式客户行；可以在备注中标记“手机号不可见，需权限处理”，但不能伪造手机号。
- 在聊天里汇报时，可根据用户当轮需求给出完整号码；如果没有明确要求，默认只做脱敏摘要。但写入飞书表必须使用完整号码。

## 去重规则

写入前先读取飞书表已有数据，按以下组合判断重复：

- `手机号` + `线索创建时间`
- 或 `手机号` + `落地页链接`
- 或同一手机号已存在且备注显示同一投放来源

发现重复时不要重复追加，只更新必要字段或报告“已存在”。

## 写入流程

1. 读取飞鱼线索列表，筛选最近投放周期或当天新增线索。
2. 找出飞书表中不存在的新线索。
3. 补齐完整手机号和关键字段。
4. 使用 `lark-cli sheets +append` 追加新行；如果表头不存在，先写入标准表头。
5. 设置日期列格式：`录入时间` 为日期，`线索创建时间/最近入池时间` 至少为可按日期筛选的日期格式。
6. 读取新增行确认写入成功。
7. 汇报：新增几条、已存在几条、是否有手机号不可见或权限阻断。

Windows PowerShell 追加示例：

```powershell
lark-cli sheets +append `
  --spreadsheet-token 'VJMOsevbJhvouRtL3mhck8wwnOf' `
  --sheet-id '1e4fee' `
  --values '[[ "待跟进", 45810, "张三", "13800138000", 45810.625, 45810.7083, "北京", "北京", "表单线索", "巨量引擎", "青鸟线索通", "新线索", "https://example.com/landing", "今日投放新线索", "优先电话联系；接通后说明来自业务流程诊断表单，再征得同意添加微信" ]]'
```

## 建议动作默认值

根据线索类型写入建议动作：

- 今日投放新线索：`优先电话联系；接通后说明来自业务流程诊断表单，再征得同意添加微信`。
- 旧真实线索：`补充电话联系；说明来自AI应用/业务流程诊断表单`。
- 测试线索：`不跟进；用于链路测试记录`。
- 手机号不可见：`先处理号码查看权限；暂不进入人工电话跟进`。

## 投放监控联动

每次启用投放后，如果创建 heartbeat 自动检查任务，必须把本 Skill 的线索同步要求写入自动化 prompt：

- 每次检查投放数据时读取 `转化数/线索数`。
- 如果用户要求实时入表，线索数增加时立即进入飞鱼 CRM 拉取新增线索完整信息并写入飞书表。
- 如果用户要求按投放轮次入表，则线索数增加时先记录“待整理”，不提前写表；达到暂停阈值后再统一整理并写入飞书表。
- 如果达到投放暂停阈值，先暂停项目/单元，再同步本轮新增线索，再做复盘。

不要只报告“有线索”。到达用户指定的入表触发点后，必须完成线索入表，除非飞鱼权限、手机号不可见或页面异常阻断。

## 安全边界

- 不要代替用户拨打电话、添加微信、发送短信或联系客户，除非用户明确授权。
- 不要点击一键起量、加速曝光、提高预算、智能托管、自动扩量。
- 不要修改广告预算、素材、落地页、定向或文案，除非用户明确要求。
- 不要在没有完整手机号的情况下虚构客户资料。
- 写飞书表是允许动作；删除飞书表数据或覆盖大范围数据前必须单独确认。
