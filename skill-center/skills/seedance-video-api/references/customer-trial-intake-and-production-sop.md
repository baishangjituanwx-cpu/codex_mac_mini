# 客户试用资料接收与视频生产 SOP

## 客户资料接收文案

您好，试用宣传视频请您发我这些资料：

1. 行业/品类
2. 品牌或门店名称
3. 想宣传什么：行业、门店，还是具体产品/服务
4. 1-5 张清晰参考图
5. 主营产品/服务和核心卖点
6. 目标客户是谁
7. 是否有价格、活动、地址等必须出现的信息
8. 视频风格偏好
9. 不能出现或不能夸大的内容

资料越具体，视频越贴近您的业务。

## Codex 后续处理规则

用户会把客户按上述 9 项填写的资料原封不动发来，并同时提供 1-5 张参考图。收到资料后，不再要求用户手动编写具体视频提示词。Codex 必须根据客户资料、参考图、行业角色提示词库和本线程视频生成硬规则，直接生产视频生成所需文件。

## 必须产出的生产文件

每次进入视频生成前，必须至少产出或更新：

1. `brief.json`: 结构化客户资料、行业、品牌、卖点、目标客户、必须出现/禁止出现信息。
2. `spoken-script.lock.md`: 生成前锁定口播脚本，作为唯一口播来源。
3. `dialogue-timeline.json`: 口播时间轴、人物、每句台词、字幕白名单。
4. `script-fingerprint.json`: 锁定脚本哈希，用于防止生成前后脚本被悄悄改写。
5. `video-prompt.txt` 或版本化 `video-prompt-vXX.txt`: 完整 Seedance 视频提示词。
6. `seedance_payload.json` 或版本化 `seedance_payload_vXX.json`: 可提交 API 的请求体。
7. 生成后检查文件：记录任务号、视频路径、字幕/口播检查结果、是否合格。

## 口播脚本硬要求

口播脚本必须严谨、清晰、语句通顺、语意明确，符合中文普通话表达习惯。不能像机器翻译、不能像生硬广告清单、不能堆砌客户资料。

口播脚本必须先锁定再进入视频生成。生成提示词和 API payload 必须逐字使用锁定脚本，不得在提交前临时改写。

## 防漂移要求

每次视频生成提示词必须包含：

- 字幕白名单硬规则。
- 对白与字幕硬要求。
- 口播与字幕逐字一致要求。
- 不得自创、改写、增删、同义替换或显示其他文字。
- 不得出现客户未提供或不能核实的夸大承诺。
- 不得出现客户明确禁止的内容。

## 资料转脚本原则

1. 客户资料中的行业、品牌、产品、卖点、目标客户是脚本依据。
2. 地址、价格、活动等信息只有客户明确要求必须出现时，才放入口播或画面要求。
3. 如果信息太长，优先放进结构化 brief，不强行塞进口播字幕。
4. 口播优先短句，建议 4 句版本，每句 3-8 个汉字，降低字幕漂移概率。
5. 每句口播必须能独立听懂，不能依赖前后文才能理解。
6. 不使用“最、第一、全网最低、保证、治愈、稳赚”等未经证实或高风险表达。

## 客户试用默认视频结构

默认生成 15 秒、9:16、720p、真实探店/口播类视频：

- 0-3 秒：门店/品牌/场景第一眼，人物 A 说第一句。
- 3-6 秒：核心产品或服务，人物 B 说第二句。
- 6-10 秒：核心卖点或使用场景，人物 C 或人物 A 说第三句。
- 10-15 秒：目标客户行动场景或到店理由，人物 A 说第四句。

如果客户资料适合单人物口播，也可以只使用人物 A，但字幕白名单仍按 4 句控制。

## 合格判定

只有当生成结果满足以下条件，才能进入最终内容包：

- 视频文件下载成功。
- 有音频且不是空轨。
- 画面符合客户行业、门店或产品。
- 人物口播清楚，中文语法通顺。
- 字幕由模型生成在画面内。
- 字幕与人物口播逐字一致。
- 字幕只出现白名单内容。
- 没有错字、乱码、额外字幕、黑底字幕条、严重多行堆叠。

不合格时，必须记录失败原因，不得用后期修字幕包装为合格成品，除非用户明确修改生产规则。
