# Report Template

Use this fixed structure for every review.

```md

- review date:
- topic or package:
- source files checked:
- platforms planned:
- platforms checked:

## 2. Executive Summary

- weakest platform:
- biggest blocker:
- repeated objection:
- lead signal:
- overall judgment:

## 3. Platform-by-Platform
### {platform}
- content:
- format:
- publish state:
- first-wave metrics:
- strongest signal:
- biggest problem:
- high-value comments or DMs:
- diagnosis:
- tomorrow's action:
- decision: Keep / Cut / Retest

### {next platform}
- content:
- format:
- publish state:
- first-wave metrics:

- biggest problem:

## 4. Cross-Platform Patterns

## 5. Tomorrow's Optimization Package
- preferred main topic:
- backup topic:
- revised title directions:
- revised cover-theme directions:
- revised hook direction for the next 30-second video:
- lean: video / article / both

## 6. Write-Backs
- reusable lesson:
- memory or note updated:
- blocker to re-check tomorrow:
```

## Template rules

- If a platform was duplicate-skipped, blocked, or still under review, include it with the exact blocker or status.
- If data is missing, write `not yet visible` instead of implying failure.
- Keep raw platform wording for moderation labels, creator-center statuses, and distribution states.
- Always state the exact date being reviewed.
